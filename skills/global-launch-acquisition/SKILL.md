# 产品发布与渠道获客

把产品送到会使用它的人面前，并留下可继续服务的真实访问、试用或咨询。先打通一条可承接的路径，再按证据扩大投入。使用用户已有定位与材料，缺少其他 Skill 也能独立工作。

## 从当前任务开始

读取已有资料，确定这次要完成的渠道动作、目标受众与地区、承接页面、可用资产，以及时间、预算、服务产能和已有授权。只补问会改变选择或阻塞执行的缺口；一次渠道提交不必先做全套增长规划。

区分用户要“建议”“准备执行包”还是“实际执行”。用户已明确授权的账号、对象、内容与预算范围可以直接继续；“做方案”不等于授权发送消息、付款或公开发布。未授权时先完成可审阅的成果，再为具体外部动作取得授权。

若定位不足以判断渠道，提出暂定受众和最小验证，不重做市场研究。若素材不足，写清缺什么和用途；可完成简单发布说明，但不要以本任务替代完整定位、长文或视频制作。

## 交付一条能走通的路径

将动作连接到“谁会看到 → 为什么愿意点 → 到哪里 → 完成什么行为 → 谁接住”。选渠道时解释受众匹配、当下可达性、承接能力和机会成本；无需凑满渠道清单。优先追踪有效试用、首次完成产品任务或合格咨询，曝光、粉丝、票数、Star 只回答各自的上游问题。

完整执行包应让下一位操作者直接接手：具体渠道或候选筛选条件、资产版本、目的地、日期与时区、负责人、预算上限、执行条件和观察窗口。未知值明确标出，不写成已确认的账号、合作或排期。小任务只交付必要部分。

自行拟定的值守时段、响应时限、审核排期、付款节点和人员安排是内部建议。未获用户确认时，外发稿使用明确的待确认条件或占位，不写成团队已经承诺的服务；“每天可投入两小时”不能推导出固定客服窗口或长期响应保证。合作方接受与本方可兑现也须分别确认。

对外使用可核实的产品事实、适用条件和真实身份。保留用户提供的来源、报价币种、版本、素材授权与禁用说法。不能把草稿案例写成客户证言，不能用虚假评价、协调投票、账号伪装或处罚规避制造增长。

执行后的报告从真实状态出发：已完成、排队、待审核、失败、状态不明分别说明；具体依据见执行模块。有工具就按已授权范围完成并核验，没有工具就给待执行包和阻塞原因。

## 保存与交接

单次任务可直接交付正文。持续项目使用现有项目记录；需要新文件时用 [渠道交接模板](templates/channel-handoff.md) 的相关部分，保存在用户项目中，不放进 Skill 安装目录。不建立无用途的账本，也不在输出里保存密码或访问令牌。

交给内容制作：渠道受众、格式限制、已验证的产品事实和具体素材缺口。交给销售与客户增长：获客来源、用户主动表达的需求、已承诺事项、可联系范围和下一步。交给增长实验：实际动作和版本、目标事件、费用、分母、时间窗、数据缺失与同期变化；本 Skill 不把渠道前后变化宣布成因果效果。

完成标准是所请求的选择、执行包或已授权动作已经交付，关键阻塞有具体去向，执行状态有依据，下一步不依赖猜测。不要用增加渠道数量替代完成当前任务。
