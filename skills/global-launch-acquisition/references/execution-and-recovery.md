# 执行与恢复

用于真正的发布、排期、触达、提交或支出操作。研究、准备素材和本地草稿不需要套用全部流程。

## 执行前核对最小必要条件

确认实际账号或组织、具体对象或渠道、内容版本、链接、时间与时区、预算，以及用户已授权的动作范围。使用已有授权，不为同一范围反复索要确认；需要新授权时先做完可审阅的执行包。用户授权“发这篇到公司 LinkedIn”可执行该项，不延伸为给互动者发私信或投广告。

优先使用客户端已经提供的连接器、官方接口或浏览器。先读当前页面与账号状态；同名账号、地区页面或项目不得仅靠名称猜选。权限、凭证或工具缺失时停止相应外部动作，交付可直接执行的文本、素材、目标、设置和核验方法。

对发布与提交先查是否已有同一对象和版本的结果或待执行项。持续项目可用平台对象 ID 或“账号＋目的地＋素材版本＋计划时间”辅助去重；一个本地“未发布”标记不能覆盖平台实际已发布状态。

## 让状态有明确含义

| 状态 | 可以证明什么 |
|---|---|
| 草稿已备好 | 本地或工具草稿存在，未声称送出 |
| 已排期 | 调度服务接受了时间与内容，尚未证明实际发布 |
| 已提交／待审核 | 接收方返回回执，尚未证明外部可见 |
| 已发布／已收录 | 能通过实际对象或页面回读正确账号、内容与链接 |
| 发送已接受 | 消息服务接受请求；不等于收件、阅读或回复 |
| 已送达／已回复 | 对应服务提供该状态或可观察到真实回复 |
| 失败 | 明确失败响应，说明是否产生部分结果 |
| 状态不明 | 请求超时或证据不足，不能归为失败或成功 |

保存必要回执：动作对象、内容版本、时间与时区、平台 ID 或 URL、返回状态、已核验字段、花费和下一步。只保存令牌引用的名称，不保存密钥本身；联系方式与原始客户资料留在私有项目。

## 重试与部分成功

请求超时后先查任务、草稿、已发布对象或发送记录，再决定是否需要重试。只有确认没有产生外部结果，或官方提供可安全复用的幂等方式时，才在原授权范围内重试。状态仍不明就停住该项并解释如何核实，禁止以“再发一次看看”解决未知。

多渠道部分成功时保留成功对象，只恢复失败项。排期时间已经过去，先查是否已发；若没有，过期排期不能自动转成当前立即发布，按用户既有时间容差处理，未约定则提出新时间的具体选择。

预算或限额到达、对象不匹配、产品链路阻断、平台拒绝或素材权利变化时暂停受影响动作；保留未受影响的独立工作。出现 429 或配额限制遵从服务的重试指引，不通过换账号或反复请求绕过。

公开后发现错误先确认影响范围、当前事实和可用纠正方式。草拟更正或修改；在已授权的维护范围内执行并回读，否则为具体更正取得授权。不要自动删除真实批评、覆盖原始记录或扩散未经核实的说法。

## 交付本次实际结果

结果说明已做的动作和核验依据、没完成的原因与下一操作者，以及可观察的早期反馈。需要后续监测时给出具体检查时点；只有用户要求并且工具支持时才建立提醒或自动化，不声称“会持续看着”而没有运行安排。

UTM 或优惠码只证明追踪链的部分信息。区分点击事件、独立访客、注册、激活、客户和收入，不合并不同平台口径。让第五部分根据数据限制决定可以作何推断。
