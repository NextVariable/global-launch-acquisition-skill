# 验证记录

本轮完成两组实际模型试用：每组使用不继承开发历史的新上下文，各依次执行相同三个合成任务。保留 3 份首稿与 3 份修改后复测稿，未向执行者提供评审答案或旧输出。任务间共享各自组内上下文，不是六次独立会话。

首稿发现了实质问题：[发布首稿](forward-tests/launch.output.md)把建议的固定客服窗口写进了外发稿，而输入仅给每天两小时，无法证明具体值守承诺。运行入口因此补上“内部建议与外发承诺分别确认”，随后在新上下文重跑整组三题，没有覆盖首稿。

| 任务 | 复测观察 | 本轮判断 |
|---|---|---|
| [一人发布](forward-tests/revised/launch.input.md) | [复测稿](forward-tests/revised/launch.output.md)交付渠道与承接路径，现场核对社区规则；值守时间保留为内部建议，外发稿未写固定响应承诺 | 修复点未再出现；选的渠道仍需真实账号资格和现场检查 |
| [墨西哥创作者](forward-tests/revised/creator.input.md) | [复测稿](forward-tests/revised/creator.output.md)选择相关候选而非大粉丝数，提供西语邀约和 brief；预算、权利、双方日期与本方能力分别确认 | 可继续核验合作，未假称签约或付款；未做母语用户审阅 |
| [超时与部分失败](forward-tests/revised/recovery.input.md) | [复测稿](forward-tests/revised/recovery.output.md)保留 queued 成功项，单独处理 403，未知历史不盲目重发；正确区分日期对应时区 | 离线恢复安排正确，未模拟成真实平台操作成功 |

语义审阅由维护者完成，不是独立盲评。不同试用会选择不同渠道或安排，不能据此推断哪个版本整体更强。输入、原始输出、运行方式及方法哈希见 [manifest.json](forward-tests/manifest.json)。来源研究与含本机信息的开发材料留在私有目录。

安装结构、内部链接、客户端元数据和 skill-creator `quick_validate.py` 检查通过。运行 `python3 scripts/validate.py` 检查格式、安装边界、记录哈希及当前方法是否匹配复测快照；它不按关键词给业务内容评分。另有 [待测场景](scenarios.md)，未实际运行的任务不计入以上结果。

当前可以独立安装试用。未测量自动触发准确率、跨模型稳定性和真实渠道增长；没有完成实际账号发布、消息送达、创作者履约或投放。上述素材与客户情景均为合成测试，公开规则核对只代表运行当时，正式执行须刷新。

跨平台检查补充：许可证等无扩展名文本也固定 LF 换行，避免 Windows 检出转换导致方法快照的字节校验误报。原始模型输入、输出与运行方法没有因此改写。
