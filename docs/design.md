# 职责与设计

这部分回答“把什么产品，通过什么渠道，送到哪些人面前，并怎样确认动作完成”。它接收已知定位与内容，也接受普通产品介绍；输入不足时只补会影响当前渠道决策的部分。

入口负责识别任务、选择模块和交接。五份 references 分别处理发布选择、社媒社区、创作者合作、持续发现与实际执行。执行模块独立是因为排期、发布、审核与发送拥有不同状态和重试风险；它仅在产生外部动作时加载。没有自建 Agent、固定调度服务或必填大型账本。

## 与其他部分的边界

| 部分 | 本部分接收／交出什么 |
|---|---|
| 海外市场研究与 GTM 战略 | 接收优先用户、市场和进入条件；回传发现的渠道限制与用户信号，不在此重新选整个市场 |
| 产品定位与增长内容 | 接收有事实依据的素材与授权；交出具体渠道、格式和素材缺口，不替代完整内容制作 |
| 销售转化与客户增长 | 交出主动需求、来源、承诺、可联系范围；后续商机跟进与客户生命周期由其处理 |
| 增长实验执行与复盘 | 接收实验要求与停止条件；交出实际动作、版本、事件口径、窗口、成本和缺失项，不自行宣布因果增长 |

渠道陌生人触达的目标是建立相关参与或获客机会；一旦进入商机资格、方案、报价与成交，转给销售流程。社区侧负责成员参与环境和活动运营，产品激活、客户健康与续费问题交给客户增长。

## 方法取舍

渠道按用户路径、可达性和团队能力选择，避免平台清单替代决策。发布先验证承接，再安排依赖和回应。KOL 同时评估制作、分发与履约，预算包含使用权和额外成本。自然曝光只是付费素材假设；搜索提交只是收录流程的一步。没有固定预算对应固定注册数，也没有通用的榜单和算法口诀。

持续运营保存足够恢复执行的记录，不把本地日志当作外部状态唯一真相。超时后先查结果，部分成功只恢复失败项。现有账号授权可延续，新范围须明确；不把全部工作冻结为只做方案。

## 安装与维护

安装单元是 `skills/global-launch-acquisition`，其 references、模板和 UI 元数据一并分发。项目中的 README、验证和设计说明服务维护者，不进入模型的默认上下文。业务数据不属于安装包。

新增方法应改变真实选择或执行行为；遇到实际失败优先做窄修复。平台变化在执行时查看当前官方规则，避免将易变限制固化进维护成本高的百科。公开验证记录只报告实际运行与已观察结果，不把结构通过当成真实增长效果。
